# Daily edition update — split channel contract

## ChatGPT non-Facebook channel

1. ChatGPT updates only `data/chatgpt/editions/YYYY-MM-DD.json` and `data/chatgpt/index.json`. Facebook Favorites are captured by the desktop Codex local CLI and belong only in `data/facebook/`.
2. Read the fixed `master` HEAD, this file, `config/sources.json`, both schemas, and the current ChatGPT index before processing. Use Asia/Taipei for the edition date and the real execution time for `generated_at`. Read today's edition at the same fixed commit; a confirmed 404 is the normal "not created yet" state, not a failure or limitation, and the run must create today's edition from the index and schemas. Only non-404 read failures are errors.
3. Read complete public originals for only the configured non-Facebook URLs and queries, following each source's existing time range, limits, and rules. Do not add sources, keywords, exclusions, ranking, or login/paid-wall workarounds. Search snippets or truncated pages are not full reads and must not be summarized as news. Relative publication labels such as "9 hours ago", "15 hours ago" or "23 hours ago" are uncertain candidates, not grounds for conservative exclusion: continue to the full original and use the configured listing/archive, observed execution time, and a source timezone only when it is verifiable to resolve the calendar date. Exclude for date only after reasonable verification still cannot satisfy that source's existing date requirement. For sources that mix free and paid items, inspect all in-scope free full-text candidates before recording a paid-wall limitation; seeing one paid item does not make the source unavailable. Treat transient timeout, network, or parser failures as retriable rather than immediately unreadable: once a candidate canonical URL is known, retry that same canonical URL up to two additional times when the active reader reports a transient fetch failure. If the active environment exposes another reader/fetch mode, it may be used only to read that same original URL; search snippets, mirrors, caches, RSS excerpts, and third-party copies never count as a full-original recovery. After a source listing/status/archive is fully enumerated and acquisition positions are fixed, independent candidate originals may be read concurrently when supported, but results must still be merged in assigned acquisition order. For representative or max-N sources, do not make the final selection while known in-scope candidates remain unread merely because an arbitrary number of other originals already succeeded; either complete those reads or report the remaining failures and retry coverage as a limitation.
4. Preserve all existing ChatGPT stories, ids, ordering, original text, image URLs/credits, and source report. Deduplicate within this channel by original URL or clearly identical event; retain existing ids and append only verifiable new sources. Append new stories in source acquisition order. Do not perform cross-channel deduplication.
5. Write schema v1 with `date`, real `generated_at`, `is_demo: false`, `stories`, and `source_reports`. Each formal story needs at least one valid original source URL. Keep unknown publication time blank or omit it. Use `source_reports.configured_sources` for per-run captured/included/excluded counts and actual limitation notes; use `complete` only when every planned source was fully checked. Any unavailable or incomplete source makes the report `limited`, with the reason stated. Distinguish no new items from a failed read.
6. Write a concise title and summary for every article, rather than copying its full original into summary. For a newly added non-Facebook story, if the original source page directly provides a usable HTTPS image URL, store that URL with descriptive alt and source attribution in credit. If the source provides no image or the active tools cannot reliably obtain its source-provided image URL, `image: null` is allowed and the story must not be excluded, counted as excluded, or make the source limited solely for that reason. Existing stories keep their current image object or null unchanged. Do not download files, create temporary image files, or add image blobs to the repository. Confirm only that a stored image URL is HTTPS and source-provided; do not make an additional licensing determination or claim that public images are licensed. A missing or failed remote image is hidden by the reader.
7. Keep the ChatGPT index schema v1, with one entry per date, paths under `data/chatgpt/editions/`, correct story counts/demo flags, newest-first dates, `current` at the newest date, and real `updated_at`. Retain all existing index entries.
8. Validate JSON, schema including formats, unique story ids within this channel edition, date, and index/edition agreement. Check for secrets. Update only the current ChatGPT edition and its index.
9. Write both files atomically with Git Data API against fixed `master`; never use sequential writes or a Contents API fallback. Re-read HEAD before ref update. Only a verified HEAD race uses reload/merge and up to three retries after the initial attempt. Connector safety denial, permission denial, branch protection/validation failure, or other non-race validation errors are reported directly and are not retried as conflicts. If connector writing is denied, the existing local `automation/update_chatgpt.py publish` path may be used only when the execution environment already has an explicitly authorized `GH_TOKEN` or `GITHUB_TOKEN`; connector authorization is not a local token. Read back the created commit and current `master` to confirm the update persisted.
10. Report date, story count, ChatGPT status/limitations, and commit SHA. If source reading or writing fails, report that plainly. Do not report success without verifying the resulting files.

Facebook automation is separate: the local CLI writes `data/facebook/` and owns its index. Preserve all historical stories, editions, image references, and files; do not delete or clean them up.

## Fast path (same safety and editorial contract)

See `automation/FAST_PATH.md` for the assessment, commands and connector procedure. These operational optimizations do not authorize a daily run to edit code, configuration, schemas, prompts, frontend assets or Facebook data.

- Resolve `master` once and pin initial reads to that commit SHA, including today's edition. A confirmed 404 for today's edition is the normal absent state and must proceed to edition creation; it is not a failure or limitation. Group independent reads when the active connector supports it; otherwise use its available individual calls. Do not claim a batch facility that is unavailable. The optional local updater uses at most six concurrent read workers.
- Start source jobs from the actual configured `web_pages` count in `config/sources.json`; do not hard-code a source total. Different source jobs may run independently. Assign acquisition positions before starting: configuration array order, then original listing order within a source. Preserve these positions when appending selected new stories; never order by network completion time. Keep list/status/archive-to-full-original dependencies inside each source job and retain all existing editorial selection limits.
- Use each source's optional `discovery` array, in listed preference order, for approved status/list/archive entrances. These are entrances to the same source, not extra sources or permission to broaden its scope. Unsupported or incomplete listings require an honest limitation note, not invented completeness.
- Skip a full original only when reliable publication metadata proves the item is entirely outside that source's existing time window. Coarse dates, relative times, unknown timezones, and boundary-overlapping dates are not grounds to discard an uncertain candidate. Relative labels such as "9 hours ago", "15 hours ago" or "23 hours ago" require continued full-original/date verification rather than conservative exclusion; use listing/archive context, the observed execution time, and only a verifiable source timezone. Do not confuse event dates, page update times or sitemap `lastmod` with publication time. Continue listing pagination as needed to establish coverage. For a configured source containing both free and paid items, enumerate and read all in-scope free full-text candidates before treating paid items as a limitation; one paid item never makes the whole source unavailable. Codex status is checked every run; only add a Codex story when `Reset scheduled` has a verifiable scheduled time, retaining the source timezone when provided. If the field is empty, absent or unverifiable, publish no Codex story and record the completed check in `source_reports.configured_sources`. The Decoder retains its previous Taipei calendar-day rule. No common replacement window is introduced.
- Every included candidate still needs a full accessible original read. For a newly added non-Facebook story, use a source-provided HTTPS image URL with alt and attribution when the original source page exposes one and the active tools can reliably obtain it; otherwise `image:null` is valid and lack of an image alone is not an exclusion or limitation. RSS/list snippets are discovery only. Report each source's actual coverage and any failed or incomplete read in the existing notes field. An empty result is not proof of no new items. Preserve previous notes and archive previous report metadata in notes labelled `Previous run (historical, not current status)`; top-level counters/status describe the latest completed run, not cumulative edition size.
- Prefer `automation/validate_chatgpt.py` and the deterministic preparation in `automation/update_chatgpt.py`. Editorial relevance, provenance, complete reading, real publication times and exhaustive secret detection still require review; a passing schema is not evidence of them.
- Create one tree with both file contents inline and the fixed base tree, then one commit, then re-read HEAD immediately before a non-force ref update. Tree, commit and ref depend on each other and must remain ordered. Explicit blobs are permitted if necessary, but never a sequential Contents API fallback. Only a verified HEAD conflict triggers re-read at the new SHA, append-merge without deleting/reordering prior stories, and retry; stop after the initial attempt plus three conflict retries. Connector safety denial, permission denial, branch protection/validation failure, and other non-race validation errors are reported directly rather than retried as conflicts. If connector writing is denied, local `publish` is permitted only when an explicitly authorized `GH_TOKEN` or `GITHUB_TOKEN` is already present. If rules, sources or schemas changed, stop and recollect against the new contract. Also stop if Taipei midnight invalidates the run date.
- Read back the created commit and both files at that commit and at a freshly resolved `master`. Verify content and ancestry when master advanced. A failed or ambiguous ref update/read-back is not success, even if an unattached commit exists. A no-change rerun may return `unchanged` without a new commit.
